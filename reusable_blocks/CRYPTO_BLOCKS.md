# Copy map for reusable blocks

Use the actual tested functions in `core.py`. `canonical()` defines sorted, compact UTF-8 JSON for signatures. `aes_encrypt/decrypt` use AES-GCM; `cbc_encrypt/decrypt` use AES-CBC with PKCS7 padding (the caller supplies the key length; voting supplies 32 bytes for AES-256). `rsa_sign/verify` use RSA-PSS with SHA-256; `rsa_wrap/unwrap` use RSA-OAEP with SHA-256. `rsa_product` and `rsa_multiply_encrypted` are raw RSA arithmetic for Lab 7 only. `paillier_encrypt/add/decrypt` handle additive homomorphism. `elgamal_sign_digest/verify_digest` are toy-group educational signatures. `store.py` serializes keys/ciphertexts for persistence.

Data flow: string -> UTF-8 bytes -> AES -> encoded JSON fields. New v2 records use lowercase hex for bytes and `0x` hex for Paillier ciphertexts; legacy versionless records use Base64 bytes and decimal integers. Record -> canonical bytes -> digest/signature; verify the same bytes before decrypt. Paillier amount -> ciphertext integer -> ciphertext multiplication -> one final decrypt. Role menus do not authenticate accounts. `standalone_submissions/` has self-contained arithmetic files; `standalone_submissions/generated/` has one-file exports of the integrated scenarios. Integrated development files cannot be copied alone without bundling their imports.
