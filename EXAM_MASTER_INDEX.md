# Exam master index — start here

**Use this folder, not an old ZIP.** On a Windows exam PC, open [START_TOOLKIT.bat](START_TOOLKIT.bat): **1 readiness → 2 setup if needed → 3 builder → 11 catalog → 10 schema-driven generator**. Keep the [option 10 prompt cheat sheet](EXAM_OPTION10_PROMPT_CHEATSHEET.md) open while answering field, role, permission and blank-value prompts. Option 10 asks for fields, roles, permissions, algorithms and architecture; review its summary, generate, read the `.checklist.txt`, run the new program's `--self-test`, then exercise the actual menu. Output appears in [exam_output/](exam_output/). A TCP build produces a shared `.py` plus `_server.py` and `_client.py`; keep all three together. For a fixed lab arithmetic exercise, a direct reference program may be quicker. **Compare every requirement before selecting one.**

The full per-path [folder inventory](EXAM_FOLDER_INVENTORY.tsv) records every file and subfolder, including `.venv`, internal metadata, cached bytecode, generated data and older logs. This index lists the files worth opening under exam time pressure. Its topic coverage follows [the 82-item manual matrix](LAB_MANUAL_COVERAGE_MATRIX.md), [inferred variants](ADDITIONAL_QUESTION_COVERAGE.md), [final gaps](FINAL_GAP_REPORT.md), and [option 10 catalog](COMPONENT_CATALOG.md). **The manual PDF is at `../IS Lab Manual_merged.pdf`, outside this folder; copy it separately if the exam permits/needs it.** PDF pages: Lab 1 **9–13**, Lab 2 **14–21**, Lab 3 **22–31**, Lab 4 **32–43**, Lab 5 **46–48**, Lab 6 **48–53**, Lab 7 **54–60**, Lab 8 **61–68**.

## First minute: route the question

1. Underline **exact algorithm/mode/key size**, inputs/outputs, fields, roles, permission conditions, storage/restart, tamper tests, and client/server requirements. Use [the requirement checklist](00_START_HERE/QUESTION_REQUIREMENT_CHECKLIST.md).
2. Search **builder 11** for each security operation and read its status/dependency. For a new record workflow choose **builder 10**. For a named manual arithmetic task choose the direct program below. The [router](exam_router.py) previews older one-file examples; keyword ranking is only a suggestion.
3. Generate to `exam_output/`, read the matching checklist, run `python -B <generated.py> --self-test`, then test valid input, invalid input, tampering, restart and every requested menu path. In a TCP build start `<stem>_server.py` before `<stem>_client.py`.
4. If a requirement is absent, state the gap and build/test the smallest reusable component. Do not relabel an existing primitive or force a scenario preset to claim coverage.

## Completely unfamiliar question: recovery path

1. Write a one-page requirement table: **input → validation → output**, arbitrary **roles/operations/access**, field schema, exact algorithms/parameters, authentication/integrity/confidentiality, persistence/restart, communication/framing, and negative tests. Separate the manual's explicit requirements from inferred hardening.
2. Use builder **11** to search every required operation and dependency; compare with [catalog](COMPONENT_CATALOG.md) and [gaps](FINAL_GAP_REPORT.md). Check that combinations pass `general_builder.py:validate_config`; a role menu alone does not authenticate.
3. Use builder **10** for the closest supported composition. Enter the actual names/fields, select only compatible mechanisms, and reject a generated result if its checklist omits a required behavior. **Do not edit the generated source** to disguise an unsupported requirement.
4. For a missing requirement, locate the smallest reusable primitive in [manual matrix](LAB_MANUAL_COVERAGE_MATRIX.md), [navigation map](EXAM_NAVIGATION_MAP.md), [core](core.py) and lab demos. Implement an independent reusable extension in development source only if exam rules/time permit, then test its known vector, failure handling and integrated workflow; regenerate/retest before submission.
5. Under time pressure, submit a correct minimal runnable solution with a clear statement of what is incomplete. Never claim full SSE from HMAC equality, threshold Paillier from Shamir reconstruction, secure remote networking from plaintext TCP, or a new scenario from a similarly named preset.

## Exam PC command card — PyCharm Terminal

Open the project folder in PyCharm and open **Terminal**. The Terminal should be in the folder containing `START_TOOLKIT.bat`. Run BAT option **1** once on that PC to check Python and `cryptography`; use option **2** only if setup is needed. You do **not** need to copy or memorize this PC's `.venv`. Use the Python interpreter that passes readiness and has `cryptography>=41,<51`.

Replace `EXACT_NAME.py` with the **new filename printed after `NEW SUBMISSION:`**:

```powershell
python -B exam_output\EXACT_NAME.py --self-test
python -B exam_output\EXACT_NAME.py
```

The first command checks a temporary smoke test. The second opens the role/action menu and saves real records/keys beside the generated script. For a generated TCP application, keep the shared `.py` with both launchers; in two terminals run `python -B exam_output\EXACT_NAME_server.py` first, then `python -B exam_output\EXACT_NAME_client.py`. For older one-file examples, run `python -B standalone_submissions\generated\patient_records.py` (or the exact other example filename).

If `python` is not recognized, `py -3 -B ...` may work with an installed Python. If it reports `ModuleNotFoundError: cryptography`, the interpreter is not ready: use BAT option 2, set PyCharm's project interpreter to the Python environment created on **that** PC, and retry. The PyCharm **Run** button is also valid when its interpreter is configured correctly. The generated output is only suitable for submission after its checklist and actual menu behavior match the question; the saved `general_application_20261028_110506.py` practice file has a submitter role with no operations and must be regenerated, not submitted.
