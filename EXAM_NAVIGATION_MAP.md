# Exam navigation map

Verified against the local source on 27 October 2026. Paths below are relative to this project root. The official `../IS Lab Manual_merged.pdf` contains eight labs (Lab 1 starts at PDF p. 9; Labs 2–8 at pp. 14, 22, 32, 46, 48, 54, 61). Folders 9 and 10 are toolkit additions, not additional numbered manual labs.

## Start and decide

From this folder, use `START_TOOLKIT.bat` on Windows, or run `python -B check_setup.py` then `python -B exam_router.py`. The batch file selects Python 3.10+, runs setup, then opens the router. `exam_router.py:find_submissions`, `preview`, `preflight`, and `offer_launch` rank and preview six one-file candidates; keyword matches do **not** prove that a new question is fully answered. `requirements.txt` declares `cryptography>=41`. The textbook RSA and ElGamal standalone exercises use only the standard library. For every question: understand → classify → locate → inspect → reuse → adapt → test → explain. Use `00_START_HERE/QUESTION_REQUIREMENT_CHECKLIST.md` to check every requested field, operation, menu output, and failure path.

Read a program's `if __name__ == '__main__'` block first. Trace its called functions, then imports, then storage. Run direct commands below from this root. `python` means the interpreter accepted by `check_setup.py`.

## Labs 1–8: files, calls, and limits

| Area and exact file | Input → output; core functions and entry | Reuse/adapt and limits |
|---|---|---|
| Lab 1 `01_basic_ciphers/classical.py` | Its `__main__` prints fixed examples. `clean` keeps A–Z. `affine`, `vigenere`, `rail_fence`, `autokey`, `playfair`, `hill2` take text plus key parameters and return uppercase text. Run `python -B 01_basic_ciphers/classical.py`; import a function for other inputs. | Reuse each cipher's arithmetic. Adapt the smallest function or add a separate wrapper for a new text/output rule. Spaces/punctuation are discarded; Playfair J→I and filler remain; Hill pads odd length. This is historical, not secure encryption. No persistent files. |
| Lab 2 `02_symmetric_encryption/aes_des_demo.py` | Prompt for UTF-8 message; `roundtrip` pads, encrypts/decrypts CBC, prints ciphertext hex, equality and timing. `__main__` runs AES-128, AES-256, DES-equivalent TripleDES K,K,K and 3DES. Run `python -B 02_symmetric_encryption/aes_des_demo.py`. | Reuse timing/round-trip structure; change algorithm/mode and handling for an exact new requirement. Keys/IVs are generated in memory, not saved; outputs vary. Historical DES/3DES and unauthenticated CBC are unsuitable for modern integrity claims. |
| Lab 3 `03_asymmetric_cryptography/asymmetric_demo.py` | `elgamal_roundtrip(m)` returns ciphertext pair and recovered integer; `rabin_roots(m)` returns ciphertext and possible roots; `rsa_oaep_roundtrip(bytes)` and `ec_hybrid_roundtrip(bytes)` return ciphertext and recovered bytes. `__main__` runs examples. Run `python -B 03_asymmetric_cryptography/asymmetric_demo.py`. | Reuse primitive examples; adapt input bounds/encoding or protocol as required. Keys are ephemeral. ElGamal/Rabin parameters are tiny; Rabin needs encoding to identify the original root. EC example derives an AES key through ECDH/HKDF, not direct ECC plaintext encryption. |
| Lab 4 `04_key_management_access_control/dh_demo.py` | `exchange(p,g)` returns two public DH values and matching shared secrets; `Roles.grant`, `revoke`, `permitted` illustrate role policy. `__main__` prints one exchange and revocation check. Run `python -B 04_key_management_access_control/dh_demo.py`. | Reuse policy shape, but add authentication and durable role/key state if a question requires actual enforcement. Values and roles are in memory; small DH group is a toy. |
| Lab 5 `05_hashing_integrity_networking/hash_demo.py` | Prompt for text; `lab_hash` applies `(value*33 + ord(char)) & 0xffffffff` from 5381; `compare(count=50)` times MD5/SHA-1/SHA-256 over 50–100 random strings and reports observed collisions. Run `python -B 05_hashing_integrity_networking/hash_demo.py`. | Reuse the manual's 5381 formula for that exercise; adapt dataset/experiment separately. A tiny random sample cannot establish collision resistance; the custom hash is not a security hash. No files. |
| Lab 5 `05_hashing_integrity_networking/socket_hash_demo.py` | `server` reads a decimal length line and exactly that many bytes, then replies with SHA-256 hex; `client` combines two prompted parts and compares local/server hashes. Run `python -B 05_hashing_integrity_networking/socket_hash_demo.py server` in one terminal, then `... client` or `... client --tamper` in another. | Reuse framing and local comparison; adapt packet validation or authentication at the protocol boundary. Loopback `127.0.0.1`, default port 51321 (`IS_LAB_HASH_PORT` overrides); one connection; no persistent files. An unauthenticated returned hash cannot protect against an active adversary. |
| Lab 6 `06_digital_signatures/signature_demo.py` | Prompt for document text; `__main__` calls `core.rsa_keypair`, `rsa_sign`, `rsa_verify` on exact bytes and tampered bytes; then `elgamal_keypair`, `elgamal_sign_digest`, `elgamal_verify_digest` on SHA-512 digest. Run `python -B 06_digital_signatures/signature_demo.py`. | Reuse RSA-PSS signing functions for real byte-message checks; bind message/identity and verify before accepting. Demo keys are ephemeral; ElGamal group is tiny. No files. |
| Lab 7 `07_homomorphic_encryption/homomorphic_demo.py` | Fixed `__main__` calls `core.rsa_textbook_parameters`/`rsa_product` for 2×3, `core.paillier_keypair`/`paillier_encrypt`/`paillier_add`/`paillier_decrypt` for 15+25, and imports `standalone_submissions.elgamal_product.elgamal_product` for 3×7. Run `python -B 07_homomorphic_encryption/homomorphic_demo.py`. | For supplied parameters and prompts, start from the matching standalone below. RSA/ElGamal decrypt a product modulo their group modulus; Paillier decrypts a sum modulo `n`. Do not substitute one operation for the other. No files. |
| Lab 8 `08_searchable_encryption/index_demo.py` | Prompt for one keyword; `token` uses HMAC-SHA-256, `make_index` maps token→document IDs for ten in-memory documents, `search` looks up a token; AES-GCM encrypts document bytes and the client decrypts matches. Run `python -B 08_searchable_encryption/index_demo.py`. | Reuse the keyed index for exact whitespace-token matches. Add normalization/query logic deliberately for variants. No persistent index/keys; leaks repeated queries, IDs and counts; it is not formal SSE or Paillier PKSE. |

## Shared code and standalone starting points

| Exact file | Key functions, input/output, storage, and use |
|---|---|
| `core.py` | `canonical` makes stable JSON bytes; `format_version`, `encode_bytes`/`decode_bytes`, `encode_integer`/`decode_integer` support v2 hex and legacy v1 Base64/decimal. `sha256`, `sha512`, `md5` return hex digests. `aes_encrypt`/`aes_decrypt` use AES-GCM blobs; `cbc_encrypt`/`cbc_decrypt` use AES-CBC blobs. `rsa_keypair`, `rsa_sign`/`rsa_verify` use RSA-PSS; `rsa_wrap`/`rsa_unwrap` use OAEP. `save_private`/`load_private` and public counterparts handle PEM. `rsa_textbook_parameters`, `rsa_multiply_encrypted`, `rsa_product` demonstrate modular product. `paillier_keypair`, `paillier_encrypt`, `paillier_add`, `paillier_decrypt` handle modular sums. `elgamal_keypair`, `elgamal_sign_digest`, `elgamal_verify_digest` handle toy signatures. Imported by scenarios; no menu. Modify a shared primitive only if the new requirement truly changes that primitive for all callers. |
| `store.py` | `read_json` loads a path/default and rejects malformed JSON; `write_json` writes through `.tmp`. `demo_keys` creates/loads `keys.json` with AES-192 key and Paillier public/private state plus unencrypted `rsa_private.pem` (2048 bits normally; voting requests 4096). `paillier_public`/`paillier_private` convert saved numbers to ints. Do not delete keys while retaining ciphertext. For storage-format changes, update this layer and its format tests. |
| `standalone_submissions/rsa_product.py` | One-file Question A source. `parameters` prompts for `p,q,e` or `N,e,d`; `run` prompts for boxes/cost in `1..N-1`, prints ciphertexts, combined ciphertext, decrypted modular result and ordinary-product comparison; `multiply_ciphertexts` computes `c1*c2 % N`. `main` menu 1/2/0. Run directly or use `standalone_submissions/generated/rsa_product.py` for the reproducible export. No files; textbook RSA only, and ordinary equality needs product `< N`. |
| `standalone_submissions/paillier_sum.py` | One-file, prompted comma-separated nonnegative integers. `setup`, `encrypt`, `add_encrypted`, `decrypt`, `main` print ciphertexts and decrypted final sum. Run `python -B standalone_submissions/paillier_sum.py`; needs `cryptography`. No files; sum must fit below `n`; no record/role workflow. |
| `standalone_submissions/elgamal_product.py` | One-file, prompted prime `p`, generator `g`, optional private `x`, and two operands. `parameters`, `encrypt`, `multiply_ciphertexts`, `decrypt`, `elgamal_product`, `main` print pair ciphertexts and modular verification. Run `python -B standalone_submissions/elgamal_product.py`; standard library. No files; small groups and modular wrap are educational. |

## Integrated scenarios: development files and generated exports

All three development programs import `core.py` and `store.py`; their `main(directory=None)` menus store data under root `demo_data/<scenario>/`. The generated copies store data under `standalone_submissions/generated/demo_data/<scenario>/` when run in place, or beside a copied script. For a changed requirement, edit the development source, regenerate the corresponding export, and test; never hand-edit a generated copy.

| Development source → one-file export | Input, output, state and responsible methods |
|---|---|
| `10_integrated_scenarios/patient_records.py` → `standalone_submissions/generated/patient_records.py` | `PatientApp.load_dataset` imports an exact five-field JSON list or CSV into an empty `Patient_records` JSON file; `add` validates a single record. `records`, `encrypt_dataset`, `hash_record`, `sign_dataset`, `verify`, `aggregate`, `search`, `verified_record` drive menu `L`, 1–8, 9 exit. AES-GCM encrypted JSON and signed digest live in `encrypted_patient_records`; `keys.json`/`rsa_private.pem` are beside them. `search` verifies then decrypts and returns all matching five-field records. `aggregate` Paillier-adds glucose and rejects wrap. Run `python -B 10_integrated_scenarios/patient_records.py` for development, or its generated export for one-file practice. Change schema/import in `load_dataset`/`add`, operations in the narrow method, and menu in `main`; keep signed payload and tests aligned. Paper-only data needs transcription. |
| `10_integrated_scenarios/grant_portal.py` → `standalone_submissions/generated/grant_portal.py` | `GrantApp.submit` accepts ID, description, integer amount and stores AES-192-GCM description, Paillier amount, MD5 digest and RSA-PSS signature in `grants.json`; `submitted_views`, `verified`, `bounded_record`, `find`, `search`, `description_hex`, `aggregate` implement researcher/reviewer/finance views and selected ciphertext total. `checked_total_capacity` enforces a conservative aggregate bound. `main` has role menus. Run `python -B 10_integrated_scenarios/grant_portal.py` or export. Change approval/role conditions in workflow methods and `main`, protected schema in `submit` and `verified`, and tests. Roles are selectable without authentication; MD5 is collision-unsafe; local signing key and amount bound are not a cryptographic range proof. |
| `10_integrated_scenarios/e_voting_demo.py` → `standalone_submissions/generated/e_voting_demo.py` | `VotingApp.setup` saves `election.json`; `cast` validates ballot ID/candidate/period, stores `ballots.json` with SHA-512, AES-256-CBC ballot, RSA-4096 wrapped AES key, toy ElGamal signature, Paillier candidate/one-hot ciphertexts, HMAC search tokens and server signature. `verify`, `search`, `tally` check and count; `token` creates HMAC tokens; `main` has admin/voter/server/authority roles. `keys.json`, `rsa_private.pem`, `index.key` persist. Run `python -B 10_integrated_scenarios/e_voting_demo.py` or export. A new protocol requirement belongs in the relevant method and its validation/tests. Local clock is not a timestamp authority; one local Paillier private key means no threshold decryption; voter identity is unbound; HMAC lookup is not formal SSE. Do not claim the original full voting specification is met. |

## Other folders and evidence

- `09_security_tools/README.md`: manual Lab 8 additional GnuPG and Snort instructions; no Python implementation or live tool integration.
- `00_START_HERE/EXAM_EXECUTION_GUIDE.md`, `EXAM_QUICK_REFERENCE.md`, `EXAM_ROUTER.md`, `QUESTION_REQUIREMENT_CHECKLIST.md`: preparation and requirement-check documents, not executable solutions. `exam_router.py` is the actual terminal router. The router document still has an older reference to five submissions; source currently catalogs six.
- `reusable_blocks/CRYPTO_BLOCKS.md`: copy/adaptation examples; actual executable primitives are in `core.py`, and scenarios import them. Inspect source before copying a block.
- `practice_variants/README.md`: two suggested variants (grant category; diagnosis-selected glucose sum), explicitly not past questions; no variant programs yet.
- `theory/IS_LAB_ENDSEM_THEORY.md`, `LAB_7_HOMOMORPHIC_ENCRYPTION.md`, `LAB_8_SEARCHABLE_ENCRYPTION.md`, `CRYPTO_CONCEPT_MAP.md`: explanation resources; check claims against the manual and runnable code.
- `tests/test_toolkit.py`: core, patient/grant/voting, manual hash, socket, menu and lab examples. `tests/test_generated_submissions.py`: deterministic exports and isolated one-file menus/restarts/tampering. `tests/test_versioned_formats.py`: v1/v2 records and tamper checks. `tests/test_navigation.py`: router and launcher readiness. `tests/check_index.js`: browser index-page check. Run `python -B -m unittest discover -s tests -v` for Python checks.
- `tools/build_submissions.py`: `outputs` takes `standalone_submissions/rsa_product.py` plus reachable definitions from `core.py`, `store.py` and each scenario; `render_scenario` removes local imports and adjusts data path. `--check` compares generated bytes without writing. Run `python -B tools/build_submissions.py --check`; after a source edit run without `--check`, then check and test. `standalone_submissions/paillier_sum.py` and `elgamal_product.py` are independently maintained; the Lab 7 demo imports the latter.
- `index.html` is a visual launcher/reference page, not an exam submission. `sample_patient_records.json` is synthetic five-field practice input. `check_setup.py` checks Python and package availability.
