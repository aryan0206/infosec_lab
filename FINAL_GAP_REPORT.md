# Final gap report — IS Lab Endsem toolkit

## Scope and count

This is a **read-only code/manual audit**. The complete `../IS Lab Manual_merged.pdf` (68 PDF pages) was read, along with `GENERALIZATION_REPORT.md`, `COMPONENT_CATALOG.md`, the source tree and tests. No code, presets, archives or existing files were changed; no Git commands were run. The companion `LAB_MANUAL_COVERAGE_MATRIX.md` contains **82 separately counted explicit tasks and subrequirements** from Labs 1–8 and their printed additional questions. Background algorithms and the inferred questions in `ADDITIONAL_QUESTION_COVERAGE.md` are excluded from the count.

| Classification | Count | Meaning |
| --- | ---: | --- |
| Fully Supported | 9 | Runnable functionality with relevant test evidence, sometimes in a separate lab/standalone demo rather than option 10 |
| Partially Supported | 37 | A primitive or subset exists; exact vector, workflow, integration, protocol or validation is missing |
| Unsupported | 31 | No implementation of the task as stated |
| Unverified | 5 | Plausible code/documentation exists but exact operation or external-tool outcome was not verified |
| **Total** | **82** | One row per matrix ID |

These counts are conservative about exact manual wording. For example, AES encryption with generated keys is partial for a fixed-key vector; EC hybrid encryption is partial for an ECC/ElGamal request; and local Shamir reconstruction is partial for threshold Paillier decryption. A “Fully Supported” separate demo does not mean option 10 can compose it.

## Option 10: confirmed composition boundary

`START_TOOLKIT.bat` launches `master_builder.py`; option **3 → 10** calls `general_builder.py:configure`, `validate_config` and `generate`, embedding configuration into `components/general_application.py`. The menu accepts arbitrary entered role names and field names. Its schema supports text/integer/boolean, required status, text lengths/choices, integer bounds, AES field encryption, and HMAC exact-field search. Role policies cover `submit`, `view`, `verify`, `search`, `approve`, `decrypt`, `aggregate`, `keys`, `rsa_product`, `hex_dump`, `serve`, `send`; all/own records, plaintext-field equality condition, field visibility/decryption and optional shared-role PIN. Relevant test evidence: `tests/test_general_builder.py:test_arbitrary_roles_permissions_and_pin`, `test_different_schema_aes_paillier_signature_aggregate`, `test_incompatible_configurations_are_rejected`.

Selectable implemented crypto in `general_builder.py:validate_config` and `components/general_application.py` is AES-128/192/256 CBC with PKCS7 or GCM with nonce/tag; SHA-1/224/256/384/512, SHA3-224/256/384/512 and MD5 record digests; HMAC-SHA-256/512 exact indexes; RSA-OAEP SHA-256 per-record AES-key wrapping; RSA-PSS 2048/3072/4096; finite-field ElGamal signatures 512/1024; Schnorr signatures using DSA group parameters 1024/2048/3072; Paillier 1024/2048 encrypted integer sums, weighted sums and unweighted mean; local Shamir 2–8 shares; textbook RSA ciphertext multiplication; canonical JSON, persistent local files, record hash chain, nonce replay rejection, configurable 0–86400-second freshness, offset/hex/ASCII dump, and length-prefixed TCP JSON submit/serve. Tests cover selected variants, **not every size/hash/mode combination**: `tests/test_general_builder.py` exercises CBC-128, GCM-128/192/256, RSA-PSS 2048, ElGamal 512, Schnorr 1024, Paillier 1024, Shamir 2-of-3, HMAC-256/512, SHA-256/SHA3-256. `test_schnorr_generated_signature` generates directly with `general_builder.generate`, not through BAT.

`general_builder.py:validate_config` rejects unsupported AES modes/architectures and incompatible dependencies such as wrapping without an encrypted field, Shamir without Paillier, aggregate without an integer field, and TCP send without submit. `test_incompatible_configurations_are_rejected` verifies several rejection paths. The catalog is an implemented-choice catalog, **not** a promise of complete manual coverage. `general_builder.py:COMPONENTS` lists explicitly unsupported entries. The older preset-based `COMPONENT_CATALOG.md` sections describe separate fixed workflows and should not be read as option 10 capabilities.

## Highest-impact manual gaps

1. **Classical cryptanalysis and exact vectors (Labs 1–3).** `01_basic_ciphers/classical.py` transforms text but does not recover shift/affine/transposition keys or brute-force cryptograms. `02_symmetric_encryption/aes_des_demo.py:roundtrip` does not supply the manual's DES/AES fixed vectors, AES-CTR, or AES-192 round/key-schedule trace. `03_asymmetric_cryptography/asymmetric_demo.py` has generated-key/toy demonstrations, not supplied RSA/ElGamal parameters, EC ElGamal or file-transfer benchmarks. These are mostly separate educational exercises and are absent from option 10.
2. **Networked security workflows (Labs 3, 5, 6).** `components/general_application.py:frame_bytes/read_frame/serve_forever/send` supports framed TCP JSON submission and tests malformed/incomplete frames, but no multipart reassembly, signed client-origin messages, RSA/DH/ECC file-transfer protocol, TLS or benchmark harness. `05_hashing_integrity_networking/socket_hash_demo.py:client` joins prompted parts before sending one message. `Application.send` transmits a role PIN in plaintext if used; `Application.handle_packet` causes the server to sign a new record, not verify a sender's signature. TCP can be bound to an entered IPv4 address (`general_builder.py:validate_config`); the generated checklist's “loopback-only” wording is therefore too broad. A non-loopback bind would expose the unencrypted PIN and JSON unless additional transport security is provided.
3. **Key management and cryptographic protocol distinctions (Labs 4, 7).** `Application.__init__` persists unencrypted private keys and local Shamir share files; there is no KMS distribution, revocation, expiry, renewal or key-event audit. `Application.shamir_reconstruct` enables local Paillier-secret recovery, not threshold Paillier partial decryption. `Application.aggregate` enforces local nonnegative bounds and wrap checks, but no cryptographic range proof. `asymmetric_demo.py:rabin_roots` is toy arithmetic, not a Rabin KMS. `standalone_submissions/elgamal_product.py` supports a separate educational product, not option 10 composition.
4. **Searchable documents and external tools (Lab 8).** `08_searchable_encryption/index_demo.py:token/make_index/search` uses HMAC tokens but leaves returned document IDs visible. Option 10 indexes entire selected field values rather than a 10-document full-text corpus. No Paillier-based PKSE query protocol is implemented. The randomized AES/RSA/Paillier equality lookup shown in the manual's sample code is not itself a valid searchable-index design. `09_security_tools/README.md` documents GnuPG and Snort; no executed end-to-end tool workflow was verified.
5. **Integrity model.** `Application.records/verify_signature` checks signatures and local chain links, replay and freshness; `test_arbitrary_roles_permissions_and_pin` tests invalid signatures, reorder/middle deletion, replay and stale timestamps. `Application.approve` rewrites an existing record and recomputes later chain hashes, so the chain is not append-only decision history. The chain has no externally trusted head: last-record deletion or privileged rewrite can evade local-only detection. With `signature='none'`, an unkeyed digest/chain does not authenticate a writer; CBC decryption has no independent authenticated-encryption guarantee. PINs identify shared roles and local account/key files are not protected against filesystem access. These are security limits, not extra manual requirements unless a question asks for those properties.

## Smallest prioritized reusable improvement set

1. **Add missing general algorithm adapters and exact-vector tests** for classical attacks, fixed-key DES/3DES/AES modes and key-schedule trace, supplied-key RSA/ElGamal, DH/ECC hybrid transfer and benchmarks. Expose only validated variants as configurable components; keep cryptanalysis and trace work as generic operations rather than scenario presets.
2. **Add composable protocol operations** for sender-signed framed messages, authenticated key agreement, multipart/file transfer and reusable performance measurement. Generate independent client/server launchers with client-origin verification and safe transport/authentication before offering remote deployment.
3. **Add a reusable key-lifecycle service** with protected key storage, distribution/enrolment, revocation, expiry/renewal and append-only key/decision events. Treat Shamir recovery and threshold Paillier partial decryption as different catalog entries and implement/test the latter only if required.
4. **Add a document-search component** with tokenization, encrypted document storage and a tested SSE index/query flow. Define PKSE separately with a real searchable protocol; never relabel HMAC exact-field lookup or randomized Paillier equality as PKSE.
5. **Create a manual-to-test coverage harness** that runs exact provided vectors, compares generated option 10 workflows and launches the actual BAT path in a temporary output root. Keep the matrix statuses tied to tests, and leave unimplemented variants visibly unsupported.

These improvements preserve the generalized configuration model. They are priorities, not implemented changes in this audit.
